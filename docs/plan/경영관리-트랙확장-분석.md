# 경영관리 트랙 확장 분석 (2026-10-01)

주요사업 한 트랙으로 구현된 지금 시스템을 **경영관리 / 주요사업 두 트랙(메가프로세스)**으로 넓히기 위한 영향 분석과 수정 순서입니다. 이 문서는 분석이며 아직 코드를 바꾸지 않았습니다. 결정이 필요한 항목은 §9에 모았습니다.

> **2026-10-07 갱신**: 그 뒤 들어온 자료(지침 08·13 사본, 빈 양식·작성지침, 체크리스트·핵심공통항목·'25 중간보고서 지적)로 바뀐 사실·결정·단계는 [`경영관리-트랙확장-설계.md`](./경영관리-트랙확장-설계.md)가 갱신합니다(이 문서의 §3.3·§3.4·§9 포함).

## 1. 요구

1. 과제관리카드와 경평 초안 작성이 경영관리·주요사업 두 카테고리 모두에서 되어야 한다.
2. 공통 지식 파일은 경영관리와 주요사업이 분리되어야 한다.
3. 경영관리는 주요사업의 내용을 가져다 쓸 수 있으므로 권한도 부여되어야 한다(과제관리카드·경평 초안).
4. 두 트랙은 과제관리카드 양식과 작성 방식이 다르고, 그 내용은 지침(프롬프트)에 있다.
5. UI도 경영관리/주요사업 메가프로세스로 나뉘어야 한다.

## 2. 결론

- 확장은 트랙 개념을 새로 만드는 일이 아니라 **이미 있는 트랙 구분(`eval_units.track`, `knowledge_chunks.track`)을 코드가 읽도록 일반화하고, 경영관리 입력 자료를 붙이는 일**이다.
- DB 장벽은 낮고(마이그레이션은 추가형), 수정량은 TypeScript에 몰려 있다.
- 임계 경로는 코드가 아니라 **경영관리 카드 원본(기준판) 확보**다.

## 4. 설계 결정

### 4.1 트랙 설정 한 곳 (`lib/tracks`)

트랙별로 달라지는 것을 순수 모듈 하나에 모은다.

```
TrackSpec {
  id, label,
  units          // 평가단위 사전 (주요사업 BZ-1~3 + 공통지표 BZ-4 / 경영관리 MG-… )
  taskNo         // 과제번호 체계
  cardForm       // 카드 양식 모듈 (아래 4.4)
  assistGuide    // 작성지원 지침 파일 (09 / 08)
  inspection     // 점검 양식 id와 정합성 항목 (biz14 / mgmt13)
  knowledgeLayer // 공통 지식 층 규칙 (포함 트랙, 트랙 공통 단위)
  reports        // 경평 초안 지원 여부와 쪽 규칙
}
```

- **strangler 순서**: 먼저 주요사업을 이 안에 감싸 동작을 바꾸지 않고, 그다음 경영관리를 추가한다.
- `BusinessId`(BZ-1~4 고정)를 `UnitId = string` + `unitsOf(track)`로 일반화한다. TS 컴파일 오류가 수정 지점 목록이 된다.
- 문서별 전용 파서(`parsers/*`)는 문서가 트랙에 고정이라 **수정하지 않는다**. 읽는 쪽(사전·번들·가드·업로드·쿼리)만 일반화하면 된다.
- 안전망: 기존 849개 테스트(59장 왕복, 바이트 동일 렌더). 주요사업 동작은 매 단계 무변경이어야 한다.

### 4.2 트랙을 카드에 비정규화하지 않는다

대안 A) `cards.track` 열 추가, B) `eval_units` 조인 유지. 카드가 59→약 100장이라 조인 비용은 무시할 수 있고, 비정규화는 단위가 바뀔 때 동기화 위험(트리거)만 더한다. **B 채택.** 필요하면 `private.card_track(card_id)` 함수와 PostgREST 임베드(`unit:eval_units!inner(track)`)를 쓴다.

### 4.3 권한 — 담당 지정 표에 열 하나

대안 비교:

| 안 | 내용 | 평가 |
|---|---|---|
| A | `card_assignees`에 `access('write'\|'read')` 추가. `read`는 팀·트랙이 달라도 지정 가능, 쓰기는 같은 팀 유지. `can_read_card`는 read·write 모두, `can_write_card`는 write만 | 기존 담당 과제 UI·RLS 파생·감사 기록 재사용. 카드를 하나씩 지정해야 하는 번거로움 |
| B | `user_track_access(user_id, track, level)` 신설 | 한 번에 트랙 전체지만 새 표·UI·RLS 항이 생기고, 카드 전용 자료(금기 4)까지 전체 노출 위험 |
| **C (채택)** | A + 「트랙 전체 읽기 지정」 일괄 단추(그 트랙 활성 카드 전체에 read 행 삽입) | 새 권한 개념이 `access` 열 하나뿐이라 RLS 표면이 작다 |

- `guard_card_assignee`는 `access='write'`일 때만 같은 팀을 요구하도록 완화한다.
- 작성본·점검 결과·전용 자료·과제별 초안은 모두 `can_read_card`를 거치므로 **주요사업 과제별 경평 초안 열람도 자동 포함**된다(어제 40개 DB 테스트가 이 연쇄를 실증).
- 읽기 전용 표시는 기존 '주관 부서 읽기 전용' 경로(`workspaceData`의 `otherTeam`)를 재활용한다.
- 한계: 보고서 단위(`reports`, 사업 × 부서)의 `can_read_report`는 팀 기준 그대로다. 교차 열람이 필요하면 별도 항이 필요하다(요구가 과제별 초안 열람이면 불필요하다고 추정).
- 마이그레이션 시 `can_read_card`/`can_write_card`는 `rls`→`card_sync`→`assignee_access`로 덮여 왔으므로 **마지막 정의 기준 `create or replace`**, `lib/db/migrations.test.ts`에 사례를 더한다.

### 4.4 공통 지식 분리

- 저장은 이미 트랙별(`knowledge_chunks.track`, `documents.tracks[]`)이다.
- `layerOf(chunk, unit, trackSpec)`로 바꾼다. 같은 3층(① 기관 공통 ② 트랙 공통 ③ 이 평가단위 공통) 구조를 유지하고, 트랙마다 포함 트랙·공통 단위만 다르다. 경영관리 요청에 주요사업 조각이 섞이지 않는다.
- `loadBundleChunks`·`gatherInspectionKnowledge`의 `.in/.eq("track", …)`를 spec 파라미터로 바꾼다.
- 올릴 범위(`UPLOAD_SCOPES`)를 트랙 × 단위 목록으로 생성하고, 공통 자료 화면은 경영관리 / 주요사업 / 기관 공통 3분할한다.
- 크기 보호(40만 자)는 트랙 × 단위별로 따로 잰다. 경영관리 적재가 주요사업 한도를 먹지 않는다.
- 가점은 두 트랙 모두에 걸치는 교차 층으로 둘지 트랙별로 복제할지 결정이 필요하다(§9-3).

### 4.5 카드 양식 — 트랙별 모듈로 분리

- 경영관리를 주요사업 JSON에 억지로 끼우고 빈 칸으로 렌더하면 「카드는 원본 그대로」(금기 3)를 어긴다.
- `CardFormSpec`(섹션 정의·경로 라벨·고정 영역 목록·편집 대상·HWP 파서/라이터·렌더러·AI용 카드 풀이)을 트랙별로 둔다. 주요사업은 기존 코드를 그대로 감싸고, 경영관리는 새 모듈을 만든다.
- 재사용: 원본 배치 엔진(`lib/hwp/*`), 병합·패치·차이·자동 저장·버전·잠금(JSON 경로 기반).
- 고정 영역 목록(`FIXED_SECTIONS = act·plan·kpi`)은 양식별로 달라진다(경영관리는 전년도 환류·지적 및 개선방안·계량지표가 후보).

### 4.7 UI — 전역 트랙 스위치

- 대안 U1) `/m/<track>/…` 주소 접두: 북마크·`from` 돌아가기·e2e가 모두 깨져 비용이 크다. U2) `?track=` 쿼리 + 쿠키(`pdca_track`) 전역 상태: 기존 주소 유지.
- **U2 채택.** 머리띠에 「경영관리 | 주요사업」 스위치를 두고(머리 오른쪽의 화면 그룹 세그먼트 `GroupSeg`와는 위치·색을 달리해 혼동을 막는다), 모든 목록·집계는 `getTrack(user, sp)`로 단위 목록을 얻어 거른다. 한 사용자에게 한 트랙만 보이면 스위치를 숨긴다.
- 대상사업 탭(`UNITS`)은 트랙의 평가단위로, 라벨은 「주요사업 전체」→「평가 단위」류로 일반화한다.
- 현황·원장·현행화·보관함·월간 점검·경평 초안·공통 지식·사용자 화면 모두 트랙 필터를 따른다. 사용자 화면의 담당 과제는 트랙별로 묶어 보인다.

### 4.8 경평 초안(경영관리)

- `lib/reports`가 2025 주요사업 실측(46쪽)·평가내용 1~4·15±1쪽·평가위원 렌즈·전년 절 비교에 묶여 있고, 경영관리는 세부평가내용 ①~⑤에 2025 경영관리 보고서 본문이 없어 기준 자료가 비어 있다.
- 따라서 **경영관리 경평 초안은 마지막 별도 단계**로 분리한다. 그 전에는 「준비 중」 빈 상태로 화면만 연다.
- 단, **주요사업 경평 초안을 경영관리 담당자가 열람**하는 것은 §4.3의 카드 단위 읽기 지정으로 즉시 충족된다.
