## 1단계 잘림 제거 — 한 일

- 첨부는 올릴 때 kordoc으로 한 번 읽어 전체 글을 저장합니다. 이미 올린 자료는 요청 때 읽어 채웁니다(쓰기 권한이 없으면 그 요청에만 씀).
- 마이그레이션 `20260929090000_material_parse.sql`(운영 적용함):
  - `card_materials`·`report_materials`에 읽은 글 칸을 더했습니다.
  - 로그인 사용자는 읽은 글 칸만 고칠 수 있습니다(칸 단위 권한). `report_materials_update` 정책을 새로 만들었습니다.
  - `ai_requests.cache_write_1h_tokens`를 더했습니다.
- 글자 자르기를 모두 없앴습니다: 첨부 6만, 작성지원 12만, 경평 15만, 블록 고치기 6만 자, 요청마다 6건·20MB.
  - 대신 토큰 어림에 상한을 두고, 넘으면 자르지 않고 멈춰 큰 자료 이름을 알립니다(`lib/ai/budget.ts`).
- 카드 자료는 전부 기본이고 사람은 빼기만 합니다. 리뷰어 코멘트도 카드 자료 전부를 받습니다. 못 읽은 자료는 요청을 막지 않고 「AI가 못 읽음」으로 표시합니다.
- 첨부 전달:
  - 첨부는 `<source key="file:N">` 봉투로 넣고, 작성지원 인용 대조에 포함합니다.
  - 경평 숫자 대조는 첨부 전체 글로 합니다(`draftEvidence`).
- API 호출은 모두 스트리밍으로 바꿨고, 캐시 쓰기 중 1시간 몫을 따로 기록해 비용을 반영합니다.
- 확인: test 657/657, tsc, lint, build를 통과했습니다.
  - `pnpm e2e`는 운영 보호 장치(올해 보고서 23건 있음) 때문에 멈췄습니다.
  - 대신 `e2e:shots`로 8개 화면을 확인했습니다.

## 4단계 그림 처리 진행 기록(2026-09-30)

- **범위**(사용자 지시: 4단계 진행, HWPX 변환은 경평 초안 품질 이후 따로): **이미지 첨부(JPG·PNG·WebP·GIF)와 글 없는 스캔 PDF 첨부**를 light 모델(`material_describe`, Sonnet 5.5·effort low)이 보고 글로 옮겨 첨부의 전체 글로 저장. 카드 전용 자료(카드 AI·경평 초안)와 보고서 추가자료가 같은 통로(`parseAttachment`)를 씀. 그림 설명은 머리에 「[그림 설명 — AI가 … 적은 글입니다. 원본 글이 아니며 …]」 표지가 붙고 AI에는 「원문 인용에 쓰지 말고 『그림 설명에 따르면』으로 밝히라」고 첨부 머리 프롬프트로 알림. 숫자 근거 인정은 기존 정책 그대로.
