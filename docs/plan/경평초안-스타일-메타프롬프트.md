- 기관 자료(카드 글, 초안 본문, 표본의 숫자)는 이 문서와 저장소에 적지 않습니다. 생성물·측정은 git 밖 `docs/analysis/eval/<날짜>-fill/`에 둡니다.

## 스타일 규칙 S1~S7 (모든 경영관리 카드에 성립하는 일반 규칙)

| id | 규칙 | 지키는 자리 |
|---|---|---|
| S1 | 절은 원장 성과 재료 수에 맞춰 2~3개. 제목 = 수단 + 결과(바뀐 상태나 그 절이 닫는 성과의 근거 수치 하나) | 구성안 지침(절 성과 재료·제목) |
| S2 | 근거 자료에 수치 묶음(계량지표 행·월별 실적 표·실사 답변 표·첨부 표 등 같은 단위 값 3개 이상)이 있으면, 그 내용을 다루는 절에 수치 표·막대 표 같은 데이터 블록을 하나 둔다. 근거에 없는 표는 만들지 않는다 | 구성안 지침 + 구성안 검사(참고 경고) |
| S3 | 칸 도식(카드·단계·PDCA·전후 패널)은 칸마다 불릿 2개 이상, 불릿 하나 = 블록 글 한도의 불릿 글자 수(2025 불릿 기준) | 집필 지침·글 한도(완료) + 분량 보강 |
| S4 | 닫는 추진성과는 수치 칸 2개 이상을 목표로 하고, 원장 성과 재료를 다른 절과 겹치지 않게 쓴다 | 구성안 절 성과 재료 배정(완료) + 수치 칸 1개 허용(완료) |
| S5 | 계획(작성일 뒤의 일)은 절 끝 한 블록이나 한 줄. 진행형 + 시점, 완료형 금지 | 집필 지침(완료) |
| S6 | 분량은 배정의 90% 이상 | 분량 채움 보강(라운드·블록 몫 확대 진행 중) |
| S7 | 같은 수치·같은 문장을 되풀이하지 않는다. 되풀이는 화면에서 하이라이트하고, 보강이 안 쓴 원장 사실로 바꾼다 | 하이라이트·보강(진행 중) |

**하드코딩 금지**
- 규칙의 기준값은 2025 측정값(`scripts/eval/mg-fill-baseline.ts` — 쪽당 글자·수량 토큰·불릿 길이)과 규정(작성분량)입니다.
- 기준 작성본의 글·숫자·블록 라벨은 코드·프롬프트에 넣지 않습니다.
- 기준 작성본은 「규칙을 모두 넘는 예」로만 씁니다.

## 메타 프롬프트 (복사해 쓰는 본문)

> 너는 경영관리 경평 초안 스타일 작업의 운영자다. 목표는 사용자가 고른 기준 작성본의 스타일(S1~S7)이 **생성할 때마다** 나오게 하는 것이다. 그 스타일은 내용이 많고, 수치·데이터 블록이 풍부하며, 절마다 성과 수치로 닫고, 여백·되풀이가 없다. 사용자 요구 R1~R12(v3)를 하나도 어기지 않는다.
>
> ### 불변 규칙
> 1. **포장 경계**는 v3 그대로다. 근거 밖 숫자·사실과 계획을 실적처럼 쓰기는 금지하고, 같은 사실의 성과 언어 재구성과 두 원값을 함께 적은 계산값은 허용한다.
> 2. **줄이지 않는다.** 고침은 채우는 쪽이다. 자료를 빼거나 글을 줄여 규칙을 맞추지 않는다. 경영관리 경평에는 공통 지식 선별(Jev)을 쓰지 않는다.
> 3. **하드코딩 금지.** 기준 작성본의 글·숫자·라벨, 표본 카드로 갈라지는 분기를 코드·프롬프트에 넣지 않는다. 상수는 2025 측정·규정 근거를 주석에 적는다.
> 4. **층 선택.** 매번 같아야 하는 것(셈·검사·배치·보강 대상 고르기)은 결정론 코드, 문장·짜임 판단은 프롬프트다. 같은 결함을 겨냥한 기존 문장은 새 줄을 더하지 말고 고친다.
> 5. **범위.** 경영관리 프롬프트와 결정론 코드를 고친다. 그리기 규칙은 두 트랙 공용이며, 주요사업 영향을 재서 보고한다.
>
> ### 순서
> 1. **생성** — 주 표본 6-2를 앱 흐름 그대로 2회 만든다: `scripts/smoke/ai-report-mg-smoke.ts 경영관리6/6-2 <out.html> --app`(구성안 → 그대로 승인 → 집필 → 분량 보강, 저장 안 함, AI는 로컬 CLI).
> 2. **프로필** — 위 스타일 프로필을 결정론으로 재서 생성 폴더 목록(index.html)의 표에 넣는다.
> 3. **화면 확인** — `python3 -m http.server 3100 --bind 127.0.0.1`로 목록을 띄우고 경로를 사용자에게 준다. 사용자가 고른 안과 그 이유(화면 지적)를 받는다.
> 4. **차이 → 규칙** — 고른 안과 다른 안의 차이를 프로필 지표와 구성안·초안 산출물로 찾아, 모든 카드에 성립하는 규칙(S 표에 더하거나 고침)으로 옮긴다.
> 5. **구현** — 서브에이전트에게 목표·범위 파일·금지·성공 기준을 적어 맡긴다. 같은 파일을 두 에이전트에게 맡기지 않는다.
> 6. **시험** — `pnpm test`·`npx tsc --noEmit -p .`·`pnpm lint`, 화면을 바꿨으면 `pnpm build`. 판 해시가 바뀌면 `lib/prompts/prompts.test.ts`를 근거 주석과 함께 고친다.
> 7. **반복** — 1~6을 되풀이한다.
> 8. **종료** — 사용자가 「이 스타일」로 고른 안이 같은 조건 2회 생성 모두에서 프로필 기준을 넘으면(운이 아니라 규칙으로 나옴) 6-2를 끝내고, 검증 카드(12-1·2-1)로 넓힌다.
> 9. **운영 저장** — 사용자가 고른 안만, 기존 행을 백업한 뒤에 한다.
>
> 금지: 심사 점수를 목표로 삼기, 기준 작성본 문구 복사, 근거 없는 표·숫자로 데이터 블록 채우기, 운영 설정(`KNOWLEDGE_SELECT` 등) 무단 변경.
