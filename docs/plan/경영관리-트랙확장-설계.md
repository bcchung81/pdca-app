**진행 메모(2026-10-07)**
- **P 완료**: 코드(요청 목적 `layerOf`·올리기 범위·표지·프롬프트·시험) + 운영 DB 갱신(백업 → 드라이런 → 갱신 → 검증). 시험 893개 통과.
- **A 완료**: `lib/tracks`(`TrackSpec`·`BIZ_TRACK`·`MGMT_TRACK`·`DEFAULT_TRACK`·`trackSpecOfUnit`), 공통 지식 조회(`loadBundleChunks`·`gatherInspectionKnowledge`)·층 판정·지침 사본 경로(`run.ts`)·점검 양식 id·경평 화면 평가단위 조회가 스펙을 받음, 평가단위 id 타입 `UnitId` 추가. **주요사업 동작 무변경 확인**: 변경 전·후 운영 데이터로 계산한 공유 층 글 6종·점검 근거 3종·시스템 프롬프트 5종·조각 키 해시가 전부 같음, 시험 897개·`tsc`·`lint`·`build` 통과.
- **A에서 일부러 안 한 것**: ① 프롬프트 묶음 캐시 키 `기능 × 트랙`(`cachedPrompt`) — 트랙별 프롬프트 조각이 아직 없어 빈 추상화가 되므로 경영관리 AI·점검 연결(G)에서 함 ② 문서별 전용 파서·시드·평가 스크립트의 「주요사업」 리터럴 — 문서가 트랙에 고정 ③ `BusinessId`를 `string`으로 바꾸지 않음 — 주요사업 사전·파서의 빠짐없는 검사(`Record<BusinessId, …>`)를 지키려고 `UnitId`(`BZ-…`·`MG-…`·`GA-…`)를 따로 두고 조각 `business`·연결 코드만 넓힘 ④ 카드 묶음 `UNITS`·과제번호 정규식(`/^주요사업\d+$/`)·원본 양식 — 카드 양식 묶음(F)·트랙 전환 화면(E) 몫.

- **B 완료**: 층 판정·조각 로더·크기 보호(`TrackSpec.sharedUnits` — 주요사업 BZ-1~3·경영관리 지표 MG-1~14)·과제 매칭 대상 계획·매칭 처리기가 트랙을 가름. 묶음은 카드의 `knowledgeUnit`(경영관리는 카드가 속한 지표)으로 ③을 읽음. 주요사업 동작 무변경 확인(변경 전후 운영 데이터 해시 동일), 시험 903개 통과. **B에서 안 한 것**: 올리기 범위 트랙 × 단위·공통 자료 화면 3분할(C·E), 카드 → 지표 대응표와 경영관리 단위 행(C), 경영관리 지표 공통 조각의 소속 판별(지표 사전 뒤).

- **C 준비 점검(2026-10-07)**: 평가단위(`eval_units`) 행을 추가하기 전에 트랙 조건 없이 전부 읽는 곳을 찾아 고침 — 부서 화면 `내 경평 초안`(`app/(app)/my/report/page.tsx`)의 평가단위 조회에 `.eq("track", DEFAULT_TRACK.id)`를 더함(현재는 주요사업뿐이라 동작 무변경). 카드를 거쳐 읽는 나머지 조인은 경영관리 카드가 생길 때 트랙 전환 화면(E)에서 다룸.

- **F(경영관리 카드 현행화) 1차 완료(2026-10-07)**: 사용자가 지정한 8월 점검 자료(HWP·PDF)를 읽는 경영관리 카드 파서(`lib/cards/hwp/parse-mgmt.ts` — 주요사업 파서의 표 도구 재사용), 경영관리 렌더러(`render-mgmt.ts`, 편집 경로 `feedback.rows.i.self.j`·`findings.rows.i.finding.j`·`kpi.rows.i.nameRaw`·`do.monthly…`), 원본 배치 짝짓기(`layoutTaskNo`·`isCardTable`·묶음 제목 줄에서 앞 카드 배치 끊기), 저장 검증·경로 이름·작성본 비교 이름, 카드 올리기 스크립트(`pnpm db:cards-mg`, 기본 드라이런·`--write`)를 만들고 **운영 DB에 평가단위 14개·팀 8개·카드 43장**을 넣음(원본 배치 43/43장, 잇기 적중률 97.5~100%, 그림 93개). 주요사업 59장·AI 입력(공유 층 글·시스템 프롬프트·점검 근거)은 변경 전과 해시가 같음. 안전 장치: 카드 목록·집계는 트랙 필터(기본 주요사업), 경영관리 카드는 `/cards?track=경영관리`로 봄, 경영관리 카드의 AI 요청은 안내 문구로 막음(`MGMT_AI_NOTICE`), 경평 초안 화면은 카드 화면으로 돌려보냄, 주요사업 현행화 화면은 경영관리 파일을 읽지 않고 안내. **아직 안 한 것**: 현행화 화면의 경영관리 지원(파일을 다시 올려 비교·반영 — `sync.ts` 블록·위험 규칙), 지적·환류 행 추가·삭제, 경영관리 고정 영역·부서 작성본 시험, 경영관리 AI·점검(G), 14-1 카드(파일에 없음), 13-2 계량지표의 부칸(보직자·직원) 칸 겹침.

**추천 순서(남은 것): 경영관리 현행화 화면 지원 → C(경영관리 자료 넣기) → G.** P는 작고 독립이라 바로 효과가 있고, A는 눈에 보이는 변화가 없어 안전하게 먼저 끝내기 좋은 바닥 공사이며, C가 있어야 G가 가능합니다. 임계 경로는 **카드 실물 → F → G**입니다. 묶음마다 끝났다고 보는 기준은 같습니다: `pnpm test`·`tsc`·`lint`·`build` 통과 + 59장 왕복·바이트 동일 렌더 무변경, DB를 바꾸는 묶음(C·D)은 `migrations.test.ts`에 사례 추가.
