# 경평 초안 문단 품질 루프 — 메타 프롬프트 (2026-10-28)

경영관리 경평 초안을 **절(문단) 단위로 채점**하고 「검증 → 원인 → 구현 → 시험 → 다시 생성」을 돌려 품질 90% 이상에 이르게 하는 절차입니다. 사람·에이전트가 그대로 따릅니다. 기관 자료(카드 글·초안 본문)는 이 문서와 저장소에 적지 않고, 산출물은 git 밖 `docs/analysis/eval/<날짜>-para/`에 둡니다.

---

## 메타 프롬프트 (복사해 쓰는 본문)

> 너는 경평 초안 품질 루프의 운영자다. 목표는 주 표본 카드의 절별 품질 점수 90% 이상을 **2회 연속** 얻고, 검증 카드 점수가 0회차보다 떨어지지 않게 하는 것이다. 아래 순서를 지키고, 각 회차 결과를 표로 남긴다.
>
> 1. **고정** — 채점표(아래 A·B·C·D)와 심사 프롬프트를 0회차 전에 고정한다. 루프 중에 기준값·항목·심사 문구를 바꾸면 0회차부터 다시 잰다.
> 2. **생성** — 표본 카드마다 앱 흐름 그대로(구성안 → 그대로 승인 → 집필) CLI로 만든다: `scripts/smoke/ai-report-mg-smoke.ts <카드> <out.html> --app`. 저장하지 않는다. AI는 CLI만 쓴다(API 금지).
> 3. **채점** — `scripts/eval/mg-para-score.ts`로 절마다 A·C·D(결정론)와 B(CLI 심사)를 매긴다. 점수 = 통과 항목 / 전체 항목.
> 4. **원인 분류** — 실패 항목마다 한 줄: `항목 → 층(재료 · 구성안 · 집필 · 코드) → 근거(블록·글 인용)`. 재료가 없어서 실패한 것(부서 확인이 필요한 값)은 「재료 결손」으로 따로 적고 프롬프트로 메우지 않는다.
> 5. **구현** — 고칠 수 있는 것은 경영관리 프롬프트(`resources/prompts/report-draft-mg`·`report-outline-mg`)와 결정론 코드(정리·검사·렌더)뿐이다. 수정은 **규칙 수준**이어야 한다(모든 카드에 성립). 카드 고유 문구·숫자·기관명을 프롬프트에 넣지 않는다. 같은 결함을 겨냥한 기존 문장이 있으면 새 줄을 더하지 말고 그 문장을 고친다. 주요사업 프롬프트·`_shared`는 건드리지 않는다.
> 6. **시험** — `pnpm test`·`npx tsc --noEmit -p .`·`pnpm lint`가 통과해야 다음 회차로 간다. 프롬프트 판 해시가 바뀌면 `lib/prompts/prompts.test.ts` 기대값을 근거 주석과 함께 고친다.
> 7. **반복** — 2~6을 되풀이한다. 상한 4회. 상한에 이르면 멈추고 남은 실패를 층별로 보고한다.
> 8. **종료 보고** — 회차별 점수표(주 표본·검증 카드), 고친 것(파일·한 줄 이유), 재료 결손 목록(부서 확인 요청), 남은 위험.
>
> **하드코딩 금지(사용자 지시 2026-10-28)**: 표본 카드·지표·과제번호·절 열쇠로 갈라지는 분기, 표본 글·숫자·기관명을 프롬프트나 코드에 적기, 표본 점수에 맞춘 상수·예외 목록을 두지 않는다. 고침은 모든 경영관리 카드(그리고 앞으로 바뀌는 초안·화면)에 그대로 성립해야 하고, 상수가 꼭 필요하면 근거(2025 보고서 측정값·규정)를 주석에 적는다. 검증 카드 점수가 떨어지면 과적합으로 보고 되돌린다.
>
> 금지: 채점 코드·기준값을 고쳐 점수를 올리기, 지표 숫자를 프롬프트에 목표로 박기(2025 측정값 인용은 허용), 근거 없는 숫자로 칸 채우기, 【확인】 남발로 실패를 피하기(D5가 막음).

## 채점표 (절마다 · 초안 전체)

점수 = 통과 항목 수 / 전체 항목 수. 절 항목은 절마다 셉니다.

### A. 서술 충실 — 결정론, 절마다
| id | 항목 | 통과 기준 |
|---|---|---|
| A1 | 불릿 길이 | 추진성과·수치 표 값 칸을 뺀 불릿 평균 ≥ 20자 |
| A2 | 조각 불릿 | 10자 이하 불릿 ≤ 10% |
| A3 | 날짜만 불릿 | 0개(`text-shape.ts isDateOnly`) |
| A4 | 구체어 | 블록마다 수치·고유명사·인용부호 묶음 든 불릿 ≥ 1 (bullets·추진배경 제외) |
| A5 | 상자 채움 | 그 절 블록에 「칸 채우기」 경고 없음 |

### B. 핵심 전달 — CLI 심사, 절마다 (예/아니오 + 근거 인용, 인용 없는 「예」는 「아니오」)
| id | 질문 |
|---|---|
| B1 | 절 제목이 수단과 결과(무엇을 해서 무엇이 달라졌나)를 말하는가 |
| B2 | 모든 블록이 절 제목의 주장을 받치는 사실을 주는가(군더더기·빈 블록 없음) |
| B3 | 블록 사이에 같은 사실·숫자를 되풀이하지 않는가 |
| B4 | 달라진 점이 수치·전후 비교·구체 사례 중 하나로 보이는가 |
| B5 | 평가위원이 30초 안에 이 절의 핵심 한 문장을 말할 수 있는가(그 문장을 답에 적음) |
| B6 | 절의 사실이 근거(카드·첨부·전년 보고서·실사 답변)와 어긋나지 않는가 |

심사 입력 = 그 절의 블록 글(평문) + 카드 원장 글 + 구성안 재료 목록. 심사 출력 = JSON `{id, pass, quote, why}` 6개.

### C. 틀·구조·시각화 다양성 — 결정론
| id | 범위 | 항목 | 통과 기준 |
|---|---|---|---|
| C1 | 절 | 같은 도식 반복 없음 | 한 절에 같은 kind 두 번 없음(bullets·table·chart·subhead 제외) |
| C2 | 절 | 시각 블록 | 절마다 bullets·subhead가 아닌 블록 ≥ 2 |
| C3 | 절 | 이 과제만의 요소 | hub·case·quotes·voices·define·chart·compare·pdca·strategy·qa 중 ≥ 1 |
| C4 | 전체 | 모양 다양성 | 서로 다른 kind:variant 수 ≥ (bullets·subhead·band·banner 뺀 블록 수)의 1/2 |
| C5 | 전체 | 구성안 그대로 | 앱이 뺀 블록 0 · 구성안 경고(짜임) 없음 |

### D. 근거·형식 — 결정론, 전체
| id | 항목 | 통과 기준 |
|---|---|---|
| D1 | 없는 숫자 | `unknownNumbers` 0 |
| D2 | 실적 칸 계획 | 「실적 칸」 경고 0 |
| D3 | 글 모양 | 「글 모양」 경고 0 |
| D4 | 분량 | 「분량」 경고 없음(±25% 안) |
| D5 | 【확인】 | 절당 평균 ≤ 1 |
