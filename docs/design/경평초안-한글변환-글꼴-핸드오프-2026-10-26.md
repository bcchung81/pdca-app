## 2. 글꼴 결정과 근거

줄바꿈은 한글 파일을 여는 PC의 한글 프로그램이 그 PC 글꼴로 계산한다(HWPX에는 글꼴 이름만 들어감). 그래서 화면과 PC가 같은 글꼴을 쓰는 것이 조건이다.

- **글꼴 파일은 앱에 넣지 않는다**(CLAUDE.md 금기 6 그대로). KoPub 공식 약관: 무료·상업 사용 가능하지만 「서체를 서버에 탑재해 웹서비스·프로그램 내 서비스로 임베딩하면 별도 승인 필요」, 수정·판매·양도 금지. 산돌구름 소개 페이지의 「임베딩 허용」 요약과 다르므로 공식 약관(kopus.org)을 기준으로 한다.
- HY헤드라인M·맑은 고딕은 웹 글꼴로 재배포할 수 없는 글꼴로 보고(한컴오피스 전용 라이선스·Microsoft 글꼴), PC에 설치된 것을 이름으로만 쓴다.
- 이 Mac에 설치된 KoPub 2.0 TTF의 실제 이름(`mdls` 확인): 가족 `KoPubBatang`·`KoPubDotum`, 전체 이름 `KoPubBatang Light` / `KoPub바탕체 Light`, PostScript `KoPubBatangLight` 등 — 앱의 별칭 목록과 맞음.

## 3. 이번에 구현한 것(`d642b1f`로 커밋)

### 3.1 화면·한글 글꼴 이름 한 곳

- `lib/reports/report-fonts.ts`(새): 글꼴 표 `REPORT_FONTS`(갈래 body·dotum·label·head·num, 굵기 범위, `local()` 이름 = 한글 전체 이름 + PostScript·영문 이름). 여기서 만드는 것:
  - 별칭 `@font-face`(`KcaBody`·`KcaDotum`·`KcaLabel`·`KcaHead`·`KcaNum`, `src`는 `local()`만 — 글꼴 파일 없음)
  - 한글 파일 face 이름 `fontName(갈래, 굵기)` — `section-hwpx.ts HWPX_FACES`가 이것을 씀(출력 글자는 예전과 같음)
  - 감지 함수 `markReportFonts`와 내려받는 HTML용 스크립트 `reportFontsScript`
- `lib/reports/section-css.ts`: `--k-f-*` 목록을 「따옴표 별칭 → 새 별칭 → 예전 대체(Noto 등)」 순으로, `KoPubWorld…` 이름은 뺌.

### 3.2 자간 보정은 진짜 글꼴이면 끔

- 화면 CSS의 `--k-ls`(−0.083em)·`--k-ws`(+0.09em)·`--k-ls-dotum`(−0.12em)·`--k-ls-label`(−0.04em)과 제목·라벨에 박혀 있던 −0.02em(이번에 `--k-ls-head`·`--k-ls-label-t` 변수로)은 **KoPub이 없어 Noto로 KoPub 폭을 흉내 내는 값**이다. 한글 파일은 모든 글자 모양이 자간 0·장평 100이라, 진짜 글꼴 위에 이 보정이 걸리면 화면 글자가 한글보다 촘촘해진다.
- 앱 틀(`app/(app)/layout.tsx`)의 `ReportFontProbe`(`components/reports/report-font-probe.tsx`)가 한 번 재서 `<html data-kfont="body dotum label head">`(진짜 글꼴이 그려지는 갈래만)를 단다. 판단: 화면이 실제로 쓰는 굵기(본문 300·700, 돋움 700, 라벨 400·700, 제목 400)마다 그 굵기 별칭을 불러오고 캔버스 폭이 대체 글꼴과 달라야 「있음」, 갈래의 굵기가 모두 있어야 표지를 단다(일부 굵기만 있으면 브라우저가 굵게를 흉내 내므로).
- CSS `:root[data-kfont~="body"] .kca-dg-doc{--k-ls:0em; …}`처럼 그 갈래만 한글 파일 값(0)으로 덮는다(단위 없는 0은 자간 맞춤의 `calc()`에서 무효라 `0em`).
- 자간 맞춤(`lib/reports/fit-dom.ts fitTextLines`)은 표지가 달린 뒤에 돈다(`report-preview.tsx`·`draft-workspace.tsx`가 `reportFontsReady()`를 기다림). 내려받는 HTML(`sectionDocument`)도 같은 순서의 인라인 스크립트.
- 글꼴이 없는 PC에서는 표지가 비어 화면이 예전과 같다(바꾼 네 가지를 되돌리면 예전 `REPORT_CSS` 고정 해시와 같아짐을 확인). `section-hwpx.test.ts`의 CSS 고정 해시는 의도적으로 갱신했다.

### 3.3 글꼴 안내 화면

- 도움말(`app/(app)/help/page.tsx`)의 「경평 초안 글꼴」 패널(`/help#report-fonts`): 필요한 이유, KoPub 2.0 공식 링크(새 탭, `rel="noopener noreferrer"`), 윈도·맥 설치 방법, 맑은 고딕·HY헤드라인M·함초롬 안내, 「설치 뒤 브라우저를 완전히 껐다 켜기」, **이 PC 상태**(갈래마다 있음/없음 — `components/reports/report-font-status.tsx ReportFontStatus`).
- 과제별 초안 더보기 메뉴(`app/(app)/reports/cards/[uid]/derive.ts`)에 「글꼴 안내」.
- 과제별 초안 도구줄 맨 앞(`page.tsx`): KoPub(body 또는 dotum)이 없을 때만 「대체 글꼴로 보임」 칩(`ReportFontNotice`), 있으면 아무것도 안 그림.

## 5. 알려진 한계·주의

- 같은 글꼴이어도 브라우저와 한글의 조판 규칙(양쪽 정렬, 어절 줄 나눔, 금칙 처리, 자간 반올림)이 달라 **일부 줄은 다르게 끊길 수 있다** — 1번 실험으로 측정.
- 화면의 자간 맞춤(`fitTextLines`, 1~2글자 넘친 칸 글을 한 줄로)은 화면 전용이라 한글 파일에는 없다 → 그 칸은 줄바꿈이 다를 수 있음.
- 판면 어림(`fit.ts`)의 글 폭 모델은 화면 대체 글꼴 기준 그대로 — 진짜 글꼴 PC에서는 어림과 실제 줄 수가 조금 다를 수 있다(판면 판정 재점검 필요).
- 막대 그림 SVG의 `font-family="KoPubWorld돋움체, …"`(`section-html.ts miniChartHtml`)는 HTML 본문 바이트를 지키려고 그대로 둠 — 1번 실험 뒤 함께 정리.
- 별칭의 영문 이름(`MalgunGothicRegular`, `KoPubBatang Light` 등) 일부는 추정 — 한글 전체 이름이나 PostScript 이름 중 하나만 맞으면 되지만 기관 PC(윈도)에서 한 번 확인.
- A안은 1회차 방침으로 도형(그리기 개체)을 쓰지 않고 상자·화살표·막대를 표 칸·기호로 그림 — 둥근 모서리·그라데이션 같은 화면 장식은 다르게 보일 수 있다.
- 기관 PC의 글꼴 설치 권한은 보안 정책에 따라 다를 수 있음(전산 담당 확인).
