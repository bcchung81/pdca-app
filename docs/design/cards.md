    - 줄 배치를 못 쓰는 문단 모양의 최종 조판은 한글에서 확인합니다(이 맥에는 한글 뷰어만 있고 자동으로 열 수 없음. kordoc 미리보기는 떠 있는 표를 겹쳐 그려 원본 HWP도 맞지 않음).
  - 원본 배치가 없을 때(9.16 원본 서식): `lib/cards/hwp/write.ts` `cardLayout`: 카드 → 표 모델(칸마다 역할). 격자·칸 나눔은 원본 카드 표(59장 중 49장이 같은 15열 모양)와 같습니다.
  - `lib/cards/hwp/form.ts`: 역할 → kordoc 서식 프로필(열 너비·칸 테두리/채움·글꼴) → `markdownToHwpx(md, { profile })` → 마무리(`finishCardHwpx`: 쪽 여백, 세로 가운데·빈 행 높이, 문단 정렬·줄 간격·글머리 내어쓰기, 굵은 머리말·9pt 괄호 설명·파란 과제번호와 PDCA 머리글자·노란 과제명과 AI활용 항목, `<hh:bold/>` 채우기, 본문 자간 −3%, 한컴 정품 패키지 R043). 서식 값은 원본 한글 파일을 kordoc으로 읽어 잰 것입니다(주석에 출처).
  - 글은 바꾸지 않고 run만 나누므로, 내려받은 파일을 다시 올리면 같은 카드로 읽힙니다(59장 왕복 테스트가 두 길 — 원본 배치 `layoutHwpxFiles`, 9.16 서식 `buildCardHwpx` — 모두 확인).
  - kordoc이 HWPX를 읽을 때 파이프 표 칸의 굵게 등 글자 모양을 `**…**`, 특수 문자를 `\*`로 적고 칸 안 줄바꿈을 행 밖으로 내므로, 카드 파서는 HWPX에서만 이 표시를 걷고(`unmarkKordocInline`) 끊긴 행을 이어 읽습니다. HWP는 표시 없이 나오므로(글 속 `*`를 잃지 않게) 걷지 않습니다.
  - 원본의 PDCA 화살표(그리기 개체)는 칸 채움으로, 줄마다 다른 자간은 대표값으로 바꿨습니다. kordoc 미리보기(`renderDocument`)는 근사 조판이라 최종 모양은 한글에서 확인합니다.
- **과제 삭제는 보관**(`cards.status = retired` + 사유): 목록·AI·저장에서 빠지고 옆 창은 읽기 전용 안내만. 보관함(`/cards/archive`)에서 되살리고, 완전 삭제는 관리자만(과제번호를 쳐서 확인).
- kordoc(MIT, 순수 JS)은 Vercel 서버 함수 안에서 그대로 돕니다(별도 서버 없음). `next.config.ts`의 `serverExternalPackages: ["kordoc"]`와 `outputFileTracingExcludes`(쓰지 않는 무거운 선택 의존성: sharp·onnx·pdfium·puppeteer 등)를 지우지 않습니다. `lib/hwpx/postprocess.ts`(HWPX 패키지 쓰기·읽기·글자/문단 모양 도구)는 카드 한글 내려받기(`lib/cards/hwp/export.ts`·`form.ts`)가 운영에서 쓰고, 나머지 경평 초안 KCA 표준보고서 양식은 참고 구현이라 화면에 연결하지 않았습니다(틀 적재 뒤).

### 과제관리카드는 원본 그대로(한글 원본 배치)

카드 화면은 **한글 원본 파일의 배치 그대로** 그립니다(칸 폭·높이·여백, 줄 배치, 글꼴·크기·장평·자간·색, 테두리·음영·그림). 원본 배치가 없거나 맞출 수 없는 카드는 9.16 원본 양식(`lib/cards/render.ts` + `lib/cards/card.css`)으로 그립니다.

- **한글 읽기·그리기**(`lib/hwp/`, 입출력 없음): `hwp5.ts`(HWP 5 바이너리 → 모델 `model.ts`), `hwpx.ts`(HWPX → 같은 모델), `hwpx-write.ts`(모델 → HWPX), `html.ts`(모델 → HTML: 줄마다 한글이 저장한 줄 배치(lineseg)대로, 표 격자·칸 여백·바깥 여백·글자처럼 놓인 개체·묶음 도형(변환 행렬 이동·회전·크기를 바깥 묶음부터 곱해 만들 때 좌표 → 상자 좌표)·그러데이션·글자 겹침), `fit.ts`(브라우저: 실제로 쓰인 글꼴 폭을 재서 한글 자간·장평·빈칸 규칙대로 글자 간격을 맞춤, 줄이 넘치면 빈칸을 문단 「최소 공백」까지 줄이고 남는 만큼 글자 간격을 고르게 줄임). **글꼴 폭 표 같은 문서·글꼴별 상수를 코드에 두지 않습니다**(하드코딩 금지). 글꼴 파일은 앱에 넣지 않습니다(기관 PC의 한컴 글꼴을 그대로 씀, 없으면 대체 글꼴로 같은 줄 배치).
  - 원본 PDF와 대조해 정한 한글 규칙(`html.ts`): 행 높이는 칸마다 「위 경계 + max(저장한 높이, 줄 배치로 잰 내용 높이 + 안 여백) ≤ 아래 경계」를 만족하는 가장 작은 경계(병합 칸이 모자라면 마지막 행이 늘고, 칸이 엇갈린 도식 표도 열마다 쌓은 높이와 같음) · 글자처럼 놓지 않은 개체(문단 기준)는 문단 위·왼쪽 + 떨어진 거리 + 바깥 여백 자리에 띄우고 칸 내용 높이를 그 아래 끝까지 셈 · 글자처럼 놓은 개체가 줄보다 낮으면 줄 아래쪽에 붙임 · 「세로 정렬: 가운데」 문단의 저장 기준선은 줄 가운데(글자 높이 50%)라 글자 상자(기준선 위 85%)를 가운데 둔 자리로 · 줄 끝 빈칸은 조각이 나뉘어도 모두 폭 없이 · 묶음 도형은 변환 행렬(이동·회전·크기, 바깥 묶음부터)로 · 뒤집은 개체의 음수 크기는 절댓값 · 표 폭이 가장 넓은 행보다 넓으면 남는 폭은 한글이 저장한 줄 폭이 가리키는 열 경계에(증거가 없으면 행 마지막 칸이 늘어남 — `tableGrid`의 `surplusBoundary`, 주요사업3 6-가) · 진하게 한 글자는 보통 굵기 글꼴 폭으로 배치(`fit.ts`, 자간·장평이 없는 진하게 조각도 `data-b`로 맞춤) · 줄이 넘쳐 빈칸을 줄일 때도 줄 앞 빈칸은 제 폭(`.hw-lead`) · 양쪽·나눔 정렬은 빈칸에만 늘림(`text-justify:inter-word` — 크롬 기본값은 □·○ 같은 기호 옆도 늘림), 고정폭 빈칸은 늘지 않음(원본 줄에서 inline-block) · 배분 정렬은 남는 폭을 빈칸 포함 글자 사이마다 같은 양씩(마지막 글자 뒤 제외, `fit.ts`가 `data-dist` 줄을 직접 나눔 — CSS `inter-character`는 줄 앞 기준 표지 때문에 첫 글자에 두 번 줌) · 표 테두리는 칸 내용 위에(한글은 표마다 칸 배경·내용을 찍은 뒤 테두리를 마지막에 그림 — 칸보다 넓은 그림도 선 아래, 1-가 AX 붙임 그림) · 줄 끝 글자(뒤 자간 없음)는 글자처럼 놓은 개체·겹침 글자까지 본 줄의 진짜 마지막(「신규」 딱지 앞 글자는 자간을 붙이고 빈칸은 제 폭).
  - 원본 PDF와 **쪽 그림**을 겹쳐 정한 글자 밖 규칙(`html.ts`·`fit.ts`): 칸 테두리는 CSS border가 아니라 배경 층(그러데이션)으로 — 크롬 border는 굵기를 정수 CSS px로 내림·최소 1px라 0.12mm 선이 2배 화면에서 원본의 두 배·0.4mm 선은 1px, 굵기는 파일 값 그대로(한 장치 점보다 가늘면 한 점, `--hw-dp` 해상도 미디어 쿼리), 층 두께는 정수 px(1 CSS px보다 얇은 층은 크롬이 자리에 따라 그리지 않음 — 안에서 선 굵기만큼만 칠함), 점선은 원뿔 그러데이션 사분면(원본: 0.36pt 굵기·점 0.48pt·간격 0.72pt), 이중선은 가는 선 둘, 네 변을 모두 적음(CSS 변수는 상속 — 안 적으면 안쪽 표 칸이 바깥 칸 선을 물려받음), 맞닿은 칸 경계는 한 칸만 칠함(두 칸이 각자 칠하면 한 장치 점보다 가는 선이 서로 다른 점에 찍혀 두 겹 — 더 굵은 쪽, 같으면 왼쪽·위 칸이 칠하고 경계가 이웃으로 다 덮이지 않으면 칠함, `sharedEdgeSkips`) · 도형 실선 윤곽은 그림자 두 겹(바깥 반·안쪽 반) · 칸 내용은 칸의 왼쪽·오른쪽 끝(테두리 중심선, 안 여백 포함)에서 가로로만 자름(원본 PDF는 칸마다 칸 사각형으로 잘라 그림: 칸보다 넓은 안쪽 표·그림. 위·아래는 행 높이가 내용을 품고, 내용 상자로 자르면 세로 정렬로 낮게 놓인 칸의 첨자·동그라미 숫자·딱지 테두리가 잘려서 자르지 않음 — 고치는 중·리뷰 표시 칸은 자르지 않음) · 글자 음영은 줄 글자 높이 한 칸(기준선 위 85%·아래 15%, 줄에서 가장 큰 글자 높이 — `fit.ts`가 `data-sh` 조각을 줄 기준 표지로 다시 칠함), 폭 없이 놓는 줄 끝 빈칸에도 음영(`.hw-tsh`, 줄 오른쪽 끝에서 자름) · 그림 자르기는 저장된 그림 범위(`imgDim`) 기준(한글에서 잘린 부분을 지운 그림은 범위 = 자르기 크기 → 그림 전체, 주요사업2 6-가) · 한 문단의 띄운 표 + 글자처럼 놓은 표(AX 붙임 딱지, 주요사업2 2-가)는 딱지를 문단 줄(위)에, 띄운 표는 문단 위에서 세로 떨어진 자리에(`TableHost.join` — 쪽 보기 `layoutPages`, 이어 보기는 딱지를 먼저, 한글 내려받기는 한 문단).
  - 검증(원본 PDF 글자·그림 위치와 대조 — 줄의 첫·끝 글자와 줄 안 모든 글자): **쪽 보기**로 그려 원본 PDF의 같은 쪽과 절대 좌표로 대조하면 세로 0.8pt 넘게 어긋나는 줄이 59장(쪽 128개)에서 주요사업1 1-가 2~4쪽의 58줄뿐(−0.73~−1.65pt, 5~7쪽은 0 — 원본은 1-가 카드 표가 묶음 개요 표(글자처럼 놓은 21×4 표)와 한 문단이라 카드 표를 매단 줄(1.6pt)이 다음 쪽으로 밀림, 카드만 떼면 한글 규칙상 다음 덩이는 새 쪽 맨 위. 절반쯤의 −0.8pt 안팎은 「과제목적」 행이 원본보다 약 0.72pt 높은 차이). 가로·줄 안 차이로 남은 것은 ① **인쇄 해상도**(PDF는 글자 폭을 600dpi 점(0.12pt) 단위로 반올림해 쌓고 양쪽 정렬로 늘어난 빈칸의 소수 부분도 버려 긴 줄 끝이 조금씩 어긋남 — 한 걸음 0.13pt 이하, 화면에서 흉내 내지 않음), ② **인쇄한 PC의 글꼴 대체**(글꼴에 없는 글자: 한컴산뜻돋움의 '∙'·❶~❺, 맑은 고딕의 ➊➋는 Windows 글꼴 Segoe UI Emoji·Symbol로, 윤고딕 740의 '∙'은 한컴바탕으로, 그 PC에 없던 함초롬 글꼴의 ※는 Segoe UI Symbol로 — 파일 값으로 알 수 없어 특례를 두지 않음, 기관 PC에서는 한글과 같은 글꼴 목록 순서로 대체), ③ 검증용 글꼴(PDF에서 꺼낸 부분 글꼴: 진하게로만 쓰인 글자는 보통 굵기 폭이 없음(`[Do]`), 한컴 사용자 영역 기호의 코드가 바뀜)뿐. 쪽 그림(글자를 지운 PDF와 글자를 투명하게 한 쪽 보기, 1pt = 2.667점, ±2점 이동 허용)으로 대조하면 강한 차이(칸 평균 90 넘음)가 남는 쪽은 1-가 둘째~넷째 쪽(위 1.6pt)·9-가/9-나가 나눠 쓰는 43쪽·주요사업3 2-다(검증 글꼴 한컴 기호 폭)뿐이고, 나머지 차이는 선의 짙기(원본 0.36pt 선은 흐림 처리로 옅은 회색 한 점, 화면은 선명한 한 점 — 맞닿은 경계를 한 칸만 칠한 뒤 일반 차이 칸이 G1 −17%·G2 −48%·G3 −56%). 칸 채움 그림은 한글이 칸보다 조금 크게(가로 +0.36pt, 세로 약 1/픽셀 수) 놓고 칸 모양으로 잘라 그리지만, 카드의 PDCA 화살표는 단색 블록·꺾쇠라 보이는 차이가 없음(늘이기로 칸에 맞춤).
- **쪽 보기**(`lib/hwp/pages.ts`, 편집기 「이어 보기 | 쪽 보기」, 읽기 전용 `renderLayoutPages`): 한글이 인쇄할 때와 같은 자리에서 쪽을 나눔. 표를 쪽 경계에서 나누는 규칙은 원본 PDF 쪽 경계 57곳·파일 값(표 높이 = 첫 쪽 부분 높이, 쪽을 넘은 줄의 세로 위치)으로 정함 — 행이 남은 공간에 안 들어가면 그 행에서 시작하는 칸들의 줄을 들어가는 만큼(줄 아래 + 칸 위·아래 안 여백), 한 칸이라도 첫 줄을 못 넣으면 행째 다음 쪽(그 행으로 이어지는 병합 칸의 저장 높이가 남았을 때만 앞 행을 쪽 끝까지 늘림), 넣은 부분 = min(남은 공간, max(저장 높이 남은 것, 넣은 줄 + 여백, 이 행에서 시작하는 병합 칸 높이)), 다음 쪽 부분 = max(저장 높이 남은 것, 남은 줄 + 여백)이고 새 쪽 첫 줄은 한글이 적은 세로 위치에, 내용이 다 들어가고 저장 높이만 넘치면 아래로 이어지는 병합 칸이 있을 때만 남은 높이를 다음 쪽에, 행 높이는 놓인 대로 다시 셈(병합 칸 높이 − 실제로 놓인 앞 행), 조각은 본문 끝에서 max(바깥 아래 여백, 101) 위에서 끊음(`TABLE_BOTTOM_MIN`). 본문 흐름은 문단 줄·글자처럼 놓은 표(문단 정렬대로, 넘치면 왼쪽)·띄운 표(문단 위 + 세로 떨어짐)·쪽 나누기. 꼬리말(쪽 번호 자동 번호)과 쪽 번호 위치(pgnp, 「- n -」)도 원본 자리에 원본 쪽 번호로. 59장·붙임 표 111개의 첫 쪽 높이와 카드 59장의 첫 쪽 번호가 모두 파일·PDF와 같음. 고친 글(줄 배치 없음)이 든 칸은 나누지 않고 통째로. 쪽 끝에서 나뉜 문단 조각의 끝 줄은 문단 끝 줄이 아니므로 양쪽 정렬 그대로(`sliceParaLines`의 `more`). 원본에서 앞 카드 뒤 쪽 중간에 이어 시작한 카드(59장 중 주요사업1 9-나 하나)는 원본 자리에서 시작해 쪽 나뉨이 원본과 같게(`layoutStartY`), 그 위 빈자리에는 「원본에서 앞 과제가 이어지는 자리」를 옅게(`PageDeco.startNote`). 꼬리말·쪽 번호 위치는 HWP·HWPX 읽기 모두 읽고(쪽 번호 자동 번호는 `data-hw-field="page"` 자리표시 글자), 한글 파일로 내려받을 때도 원본처럼 씁니다(`hp:footer`·`hp:autoNum`·`hp:pageNum`).
