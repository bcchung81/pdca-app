# 트랙 스펙(`lib/tracks`)

CLAUDE.md의 「트랙 스펙」 절 원문입니다(2026-10-17에 CLAUDE.md를 줄이며 옮김).

트랙(주요사업/경영관리)별로 달라지는 것(공통 지식 조회 트랙·작성지원 지침 사본·종합점검 지침 사본·점검표 양식 id)은 코드에 문자열로 못박지 않고 `lib/tracks`의 `TrackSpec`(`BIZ_TRACK`·`MGMT_TRACK`)에서 받습니다 — 평가단위 id가 `MG-…`면 경영관리(`trackSpecOfUnit`), 아니면 주요사업이고 트랙을 안 정한 곳은 `DEFAULT_TRACK`(= 주요사업). 주요사업 값은 예전 리터럴 그대로라 **동작이 바뀌지 않아야** 하며(`tracks.test.ts`가 값을 못박음) 경영관리는 작성지원 지침 08·종합점검 지침 13 사본을 읽고 경영관리 전용 프롬프트 폴더를 씁니다(`card-assist-mg` 등 — 주요사업 프롬프트·판은 그대로, 경영관리 확장 설계 `docs/plan/경영관리-트랙확장-설계.md`). 문서별 전용 파서·시드·평가 스크립트의 「주요사업」 리터럴은 문서가 트랙에 고정이라 일부러 안 건드림. 평가단위 id 타입은 `UnitId`(`BZ-…`·`MG-…`·`GA-…`), 주요사업 전용 사전·파서는 `BusinessId` 그대로. **공통 지식은 트랙별로 분리**(묶음 B, 2026-10-07): 층 판정은 평가단위 트랙의 조각만, 크기 보호(40만 자)는 `TrackSpec.sharedUnits`(주요사업 BZ-1~3·경영관리 지표 MG-1~14)별로 따로, 과제 매칭 작업은 같은 트랙 카드에만 만들고, 올릴 때 크기 보호는 모든 트랙 조각(`loadBundleChunks(db, "all")`)을 넘김 — 경영관리 카드의 ③ 지식 단위는 카드가 속한 지표(`knowledgeUnit`)를 호출하는 쪽이 넘김. 상세 `docs/design/knowledge.md`.
