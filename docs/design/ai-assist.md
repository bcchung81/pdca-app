### AI 작성지원(카드 본문)

- `lib/ai/writer.ts`(요청·결과 형식·검증, 순수) · `lib/ai/context.ts`(근거 자료 모으기) · `lib/ai/run.ts`(모델 호출) · 서버 액션 `runCardAssist`.
- 시스템 프롬프트 = 앱 적응문(`resources/prompts/card-assist/system.md`) + 담당자 지침(09) + 문체 기준. 지침 본문은 고치지 않고, 앱에서 달라지는 점만 적응문에 씁니다.
- 지침 09·14의 '대상사업'(Notion 속성, 3개 문자열만 유효)은 이 앱의 **주요사업**이고 카드 기본정보 '대상사업' 칸은 그 아래 세부 대상사업입니다. 작성지원·코멘트·질문 적응문에 대상사업 주의(`resources/prompts/_shared/card.md#target-business`)를 끼우고 카드 풀이(`cardOutline`) 첫머리에 주요사업 이름을 적습니다 — 빼면 AI가 「대상사업이 3개 중 하나가 아님」으로 잘못 짚습니다(실측).
- 결과는 구조화 출력(zod). 인용은 모델이 낸 원문 구절을 서버가 근거 자료와 대조해 "원문 확인/다름"으로 표시하고, 반영 제안은 카드에 실제 있는 글 칸 경로만 "카드에 반영" 버튼을 켭니다.
- 모델은 등급 표(`lib/ai/models.ts` `FEATURE_TIER`: 작성지원·질문·코멘트는 heavy)로 정함 — 2026-09-30부터 heavy 기본은 `claude-sonnet-5-5`·effort `xhigh`(`CLAUDE_MODEL_HEAVY`·`CLAUDE_EFFORT_HEAVY`, 옛 `CLAUDE_MODEL_WRITER`도 읽음). 예전 기본은 Opus 5.5(평가·품질 확인을 Opus 5.5로 함 — Sonnet 5.5로 바꾼 뒤의 품질 비교는 아직 없음). 호출 기록은 `ai_requests`(토큰(입력·출력·캐시 읽기·캐시 쓰기 `cache_write_tokens`)·오류만, 본문 저장 안 함), 1분 5회 제한. 관리자 「AI 사용량」은 `lib/ai/pricing.ts`(모델별 단가, 2026-09-28 docs.claude.com 기준)로 추정 금액(USD·원화 1,400원 가정)을 보이고, CLI로 돈 기록은 실제로는 구독이라 「API 환산」으로 표시합니다.
- **기능별 effort(2026-10-07, `lib/ai/models.ts` `FEATURE_EFFORT`)**: 작성지원·질문·코멘트·블록 고치기는 `high`, 월간 점검·경평 구성안·집필(판면 고치기 포함)은 등급 기본 `xhigh`, light는 `low`. 우선순위는 환경변수로 명시한 등급 effort(`CLAUDE_EFFORT_HEAVY`·`CLAUDE_EFFORT_LIGHT`, 옛 `CLAUDE_CLI_EFFORT`는 CLI 경로) > 기능별 표 > 등급 기본값. 같은 기능은 한 값이라 같은 기능끼리의 캐시 공유는 그대로. 근거(1-가 카드·CLI, xhigh→high 출력 토큰): 개선 제안 −56%(블라인드 심사 3카드 변동 범위 안, 다만 인용 수는 줄어 전부 넣기끼리 재현 69% 대 58%) · 질문 −41%(품질은 심사 안 함) · 코멘트·블록 고치기는 측정 없이 범위가 좁고 코드가 숫자·칸을 검증하며 수정 이력으로 되돌릴 수 있어 같은 값으로 낮춤. **미측정 위험**: 작성지원 중 보완 점검(행별 판정)·실적 발굴·실적 반영은 개선 제안 외에는 심사 안 함 — 품질이 떨어지면 `CLAUDE_EFFORT_HEAVY=xhigh`로 되돌리거나 표 한 줄을 고침. 비용 영향은 `docs/analysis/AI-요청-구성과-비용-조사.md` 9.10.
- **요청 종류는 넷**(`WRITER_MODES`): 「개선 제안」(`improve` — 지침 <작업절차>가 함께 붙이라는 지적사항 환류·전략연계 점검·점검 대비 귀띔을 한 요청으로, summary는 ◆ 세 갈래, 카드 반영 제안은 우선순위 순 8건까지 — 코드가 `SUGGESTION_MAX`로 자름), 「실적 발굴」(모드 B), 「실적 반영」(모드 A), 「보완 점검」(모드 C, `followup` — 아래 「보완 점검」 절). 지침 09의 정식 모드는 A·B·C이고, 옛 「점검 대비 리뷰」(`review`)·「개선방향 제시」는 「개선 제안」으로 합쳤고 「선택한 칸 다듬기」(`polish`)는 드래그 「AI 수정 요청」이 맡아 없앴습니다. 이 탭에 남은 옛 기록은 `LEGACY_MODES`로 옛 이름 그대로 보이고, 사용량 화면은 옛 행을 「(이전)」으로 표시합니다. 모든 요청 종류·질문의 시스템 프롬프트는 같고(적응문 + 지침 09 전문 + 문체 기준), 요청 글의 「할 일」(`card-assist/request.md` task.*)이 지침의 절을 가리킵니다.

- **첨부(모든 요청 종류와 「질문」, 참고자료 설계 1단계 2026-09-29 — `docs/reference-materials.md`)**: 파일을 AI 작성지원 옆 창 어디에나 끌어 놓거나 📎로 고르면 브라우저가 카드 전용 자료(`card-materials/{uid}/…`)로 서명 업로드하고(`uploadSigned` — Vercel 함수 본문 한도와 무관, 파일당 50MB까지) 서버가 올리는 즉시 kordoc으로 한 번 읽어 전체 글을 저장합니다(`card_materials.parsed_text` 등, `lib/ai/material-text.ts`). 입력칸 위 첨부 칩으로 그 요청에서 고르고, 이미 올린 자료는 「카드 자료 N ▾」에서 고름 — 요청 종류·질문·리뷰어 코멘트 모두 **이 카드의 카드 전용 자료 전부가 기본**이고, 화면에서 뺀 것(`exclude_ids`)만 빠집니다(사람의 선택은 「빼기」로만). 요청은 자료 id만 보내고 서버(`loadCardFiles`)가 그 카드의 `card_materials` 안에서만 찾아 사용자 권한으로 읽습니다(다른 카드 id는 「찾을 수 없음」) — 저장본이 있고 파서 판이 같으면 그대로 쓰고, 없거나 판이 다르면 그 자리에서 다시 읽어 채웁니다(`loadMaterialTexts`). **글은 자르지 않습니다**(예전 `CARD_ATTACH`·`fitFileTexts` 없앰) — 대신 시스템 프롬프트 + 요청 글 전체가 토큰 상한(`INPUT_BUDGET` 40만, `lib/ai/budget.ts` `checkBudget`)을 넘으면 자르지 않고 멈춰 큰 자료 이름을 알립니다(`BudgetError`). AI가 못 읽는 형식·읽기 실패 파일(스캔 PDF 등)은 요청을 막지 않고 「AI가 못 읽음」으로 빠지며 자료 목록에 표시합니다. 올린 자료는 카드에 남아 경평 초안 과제별 초안의 첨부 후보가 됩니다. 부서 화면 보기(미리보기)에서는 올리기를 숨김. 「실적 반영」은 첨부 또는 요청 칸에 붙여 넣은 실적 글이 있어야 합니다. **입력칸은 요청 칸 하나**입니다(예전에 실적 반영만 따로 뜨던 붙여 넣기 칸은 없앴음): 실적 반영이면 요청 칸 글(실적 문장·수치와 요청이 섞여도 됨)을 서버가 2만 자까지 「실적 자료·요청」으로 프롬프트에 넣고(`note`는 비움), 다른 요청 종류는 요청 내용 2천 자, 질문은 4천 자 — 화면 maxLength와 서버 자르기가 같은 값(`ASSIST_TEXT_MAX`·`CHAT_LIMITS.question`, 이 요청 글 한도는 그대로 둠). 말풍선은 실적 반영의 긴 글을 앞 160자 + 「붙여 넣은 글 N자」로 줄여 보입니다(`askLines`의 `clip`). 예전의 3.5MB 바로 붙이기는 없앴습니다.

- 삭제는 AI 없이 바로 지웁니다(뒤 칸부터, 비게 된 줄은 줄째) + 알림의 「되돌리기」. 좋음은 여백 메모만 남기고 다음 AI 요청에 「유지할 부분」으로 함께 보냅니다.
- 수정 요청·질문은 여백의 작성 카드(⌘↵)로 보냅니다 → 「보냄」(5초 안 되돌리기) → 마지막 코멘트 5초 뒤 모인 코멘트를 **한 번에** 서버 액션 `runCardComments`로(최대 12개, 처리 중에 쌓인 것은 다음 묶음) → 반영됨·답변·반영 안 함·충돌. 여백 메모는 칸 높이에 맞춰 서고, 누르면 그 칸으로 갑니다.
- 순수 로직: `lib/ai/comments.ts`(적응문은 `resources/prompts/card-comment/system.md`, 편집할 수 있는 칸 전부를 [줄]·[칸]·잠김으로 적은 카드, 결과 검증 — 실제 `data-p` 칸·잠김·줄/칸 조작만 통과, 질문은 답만), `lib/cards/patch.ts`(편집 한꺼번에 적용·합치기·코멘트별 되돌리기), `lib/cards/path-label.ts`(경로 → 「[Plan] 3번째 줄」 같은 자리 이름). 화면은 `components/cards/review/`.
- 근거는 공통 지식 규칙 범위 전부(작성지원·질문과 같은 `loadCardBundle`) + **이 카드의 카드 전용 자료 전부**(작성지원·질문과 같은 `loadCardFiles`, 저장본 전체 글 — 참고자료 설계 1단계 전에는 첨부를 안 봤음). 「첨부 기준으로 수치 고쳐 줘」 같은 코멘트도 근거로 처리합니다.
- 합치기: AI는 **보낼 때 카드** 기준으로 편집을 돌려줍니다. 화면은 묶음(글줄이면 가장 바깥 줄 목록, 칸이면 그 칸)마다 "보낼 때 값 = 지금 값"일 때만 반영하고, 기다리는 동안 사용자가 고친 묶음은 덮지 않고 「충돌」로 제안 글을 보여 줍니다. 되돌리기는 코멘트별이고, 그 뒤 같은 묶음을 또 고쳤으면 막습니다.
- 서버는 카드를 저장하지 않습니다. 반영된 카드는 평소 자동 저장(원장 `saveCard`·작성본 `saveDraft`)으로 저장되고 수정 이력에 남습니다. 부서 작성본에서는 잠긴 고정 영역을 AI가 고치지 않습니다(서버 `editTargets(card, locked)`).
- 코멘트 메모는 이 브라우저 탭에만 둡니다(sessionStorage `card-review|<uid>`). AI가 처리하는 중에 옆 창을 닫으려 하면 확인 막대를 띄웁니다(닫으면 결과를 반영하지 못함).
- 호출 기록은 `ai_requests.feature = card_comment`(mode는 종류별 개수, 예: `edit:2,ask:1`). AI 작성지원과 합쳐 1분 5회입니다.
- `::highlight()`(고른 글 칠하기)는 CSS 빌드 도구가 아직 몰라 `card-editor.tsx`의 `<style>`에 둡니다.
