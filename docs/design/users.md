# 사용자 등록·과제 담당자

CLAUDE.md의 「사용자 등록·과제 담당자」 절의 상세(2026-09-30).

## 무엇을 하나

- 성과관리팀·관리자가 **부서 담당자 계정**을 만들고(개별 추가 / 일괄 등록), 팀을 정하고, 사용 중지·복구하고, 과제마다 **담당자**를 지정한다.
- 역할은 여전히 셋(`dept_user` < `pmo` < `admin`). 이 기능이 만드는 계정은 부서 담당자뿐이다.
- 접근 범위는 **담당자 지정 기준**(2026-10-01, `20261001100000_assignee_access.sql`): 성과관리팀·관리자는 모든 과제, 부서 담당자는 `card_assignees`에 지정된 과제만 읽고 쓴다(`private.can_read_card`·`can_write_card`). 같은 팀이어도 지정 안 된 과제는 안 보이고, 주관 부서의 「그 사업 카드 전체 읽기」 예외는 없앴다. 이 마이그레이션은 기존 지정을 그대로 두고 팀 전체를 다시 채우지 않으므로, **적용 전에 부서 담당자마다 담당 과제가 지정돼 있는지 확인**한다(지정이 없으면 과제가 하나도 안 보임).
- 보이는 과제가 줄어드는 곳: 내 과제(`/my`, `listCards({ assigneeId })`로 명시)와 점검 결과·작성본·전용 자료·과제별 초안·메뉴 배지처럼 카드에 딸린 모든 표. 보고서(사업 × 부서) 단위는 팀 기준 그대로라, 부서 담당자가 제출 가능 여부를 볼 때 자기에게 지정된 과제만 셈에 들어간다(팀 전체를 지정해 두면 같음).

## 일괄 등록 (`/users/import`, 엑셀 붙여넣기)

화면은 **엑셀처럼 생긴 격자**(오픈소스 Jspreadsheet CE 5.0.4, MIT — 글자 머리·줄 번호·칸 선택·방향키·복사/붙여넣기·우클릭 메뉴·열 너비 조절)입니다. 모양은 엑셀 365 기본값을 따르고(`paste-grid.css`: 눈금선 #D4D4D4·머리 #E6E6E6·활성 칸 초록 #217346 테두리·선택 영역 연한 초록·줄 높이 20px·「좋음 #C6EFCE/#006100 · 보통 #FFEB9C/#9C5700 · 나쁨 #FFC7CE/#9C0006」 셀 스타일 색, 열 글자 A~G 줄을 열 이름 줄 위에), 카드 외곽·둥근 모서리·그림자는 두지 않고 격자 바로 아래에 엑셀 상태 표시줄 모양의 요약 줄을 붙입니다. 격자는 빈 줄 100개가 이어지고 창 높이에 맞춰 화면 하단까지 늘어나며(창 크기를 따라감, 작은 창에서는 최소 360px), 빈 줄에는 체크박스·드롭다운 화살표를 그리지 않습니다. 제목 아래 설명 문장은 두지 않습니다(화면 제목만). 열은 A 이름 · B 이메일 · C 팀명(엑셀에 적힌 그대로) · D 권한(관리자에게만 보임 — 성과관리팀 사용자에게는 숨은 칸이고 늘 부서 담당자) · E 팀(추천·확정, 본부별 드롭다운) · F 추천 후보·근거 · G 상태 · H 반영(체크) · (숨은 열 auto = 앞서 자동으로 채운 팀).

1. **붙여넣기**: 엑셀·구글 시트·한셀에서 이름·이메일·팀명 영역을 복사해 격자 **첫 칸(1행 이름)**에 붙여넣는다(Ctrl+V). 격자가 탭 구분 글(여러 줄·탭·따옴표 셀 포함)을 칸으로 나누고, `onbeforepaste`에서 `parsePasteTable`(`lib/users/paste.ts`)이 머리글 줄은 버리고 「@가 든 열」을 이메일로 보고 셀 안 줄바꿈을 공백으로 고쳐 A~C 세 열로 넣는다. 붙여넣은 줄은 D~G·H를 비우고 새로 분석한다(앞 사람의 팀 선택이 남지 않게). 칸을 직접 고치거나 줄을 끼우고 지워도 다시 분석한다.
2. **분석**(`analyzeGrid`, `lib/users/grid.ts`, 순수): 줄마다 팀 표기를 카드가 연결된 활성 팀과 견주고(`matchTeam`) 팀·후보·상태·체크를 계산해 D~G에 써넣는다. 이미 있는 계정 여부만 서버(`lookupExistingUsers`, DB를 바꾸지 않음)에 새 이메일만 묻는다(조회 전에는 「확인 중…」).
   - **초록**(팀명 정확히 일치 — 자동 확정): D가 채워지고 G가 체크된다.
   - **노랑**(추천만 채움): 분명한 1순위(점수 0.9 이상이고 2순위보다 0.1 이상 앞섬, 예: 끝말만 다름 97%)는 D에 미리 채우되 G는 꺼 둔다. 그보다 약하거나 후보가 붙어 있으면 D를 비우고 E에 후보와 점수만 보여 준다 → 사람이 D 드롭다운(본부별, 이름 치면 걸러짐)에서 고르면 **그 줄이 곧바로 체크**된다(고름이 곧 확인).
   - **회색**(건너뜀: 성과관리팀·관리자 계정·중지 계정·기관 밖 메일) · **붉은색**(오류·중복).
   - 계산 열을 써넣을 때는 되돌리기 기록에 남기지 않는다(`ws.ignoreHistory`). 사람이 고른 팀(D ≠ H)은 팀명 글을 고쳐도 그대로, 자동으로 채운 팀(D = H)은 글을 따라간다.
3. **요약 줄**: 입력 n줄 · 반영 예정 · 확인 필요 · 건너뜀/오류, 「팀 과제 자동 매칭」 체크, 「추천 모두 적용」(노랑 줄을 체크하고, 팀이 빈 줄에는 분명한 1순위를 넣고 체크 — 본부만 적힌 줄처럼 동점 후보는 고르지 않음), 「모두 지우기」.
4. **반영**(`applyUserPaste`): 체크된 줄만 보낸다. 서버가 줄 판정을 처음부터 다시 하고, 신규는 계정을 만들고(서비스 키 `createUser`, 이어서 로그인 사용자 권한으로 이름·팀 update — 반환 행 수 확인), 이미 있는 담당자는 이름·팀을 바꾼다. 「팀 과제 자동 매칭」이 켜져 있으면 그 팀 활성 과제 전부를 담당으로 지정한다. 줄마다 결과(만듦/반영/변경 없음/건너뜀/실패 + 사유)를 돌려주고, 실패한 줄은 「반영 못 한 줄 표에 다시 놓기」로 격자에 되돌려 재시도한다.

격자 라이브러리는 브라우저 전용이라 화면이 뜬 뒤 동적으로 불러온다(`import("jspreadsheet-ce")`). 이벤트(`onbeforepaste`·`onpaste`·`onchange` …)는 **스프레드시트 옵션(루트)**에 달아야 하고(워크시트 옵션에 달면 안 불림), `onbeforepaste`가 받는 열·줄 번호는 문자열이며 **돌려주는 값은 문자열 2차원 배열**(타입 정의는 문자열이라 적었지만 실제로는 배열)이다. `onpaste`가 주는 값도 타입(2차원)과 달리 칸마다 평평하게 나열되고 열·줄 번호가 `"0"+1` 같은 문자열 이어붙이기로 깨져(1줄이 "10") 믿을 수 없으므로, 붙여넣기 직전(`onbeforepaste`)에 시작 줄과 줄 수를 직접 기억해 쓴다. 헤드리스 Chrome 시험에서 머리글 제거·따옴표 줄바꿈·줄 자동 추가(9줄 붙여넣기 → 9줄)·본부 그룹 드롭다운·칸 색칠을 확인했다.

### 성과관리팀 권한 등록(관리자만)

관리자는 도구줄의 **「붙여넣는 줄 권한」**(부서 담당자 / 성과관리팀)을 고르고 붙여넣거나, 줄마다 D열 「권한」 드롭다운으로 바꾼다. 성과관리팀 줄은 파란 칸으로 보이고 고른 것이 곧 확인이라 바로 체크된다.
- 성과관리팀은 모든 과제를 보므로 **팀 없이 등록할 수 있다**(팀 칸이 비어 있어도 「팀 선택 필요」·노랑이 아님, 추천 팀도 미리 채우지 않고 팀명이 정확히 같을 때만 넣음, 「팀 과제 자동 매칭」은 적용 안 함). 기관 밖 메일도 등록할 수 있다(관리자).
- 이미 있는 계정: 부서 담당자를 성과관리팀으로 **올리면**(상태 「변경」, 「권한 부서 담당자 → 성과관리팀(담당 과제 지정은 해제됨)」 표시) DB 트리거가 그 사람의 담당 과제 지정을 지운다. 이미 성과관리팀이면 「변경 없음」(이름·팀만 갱신), **관리자 계정은 건드리지 않고**, 성과관리팀을 부서 담당자로 **낮추지도 않는다**(건너뜀).
- 성과관리팀 사용자가 성과관리팀 권한 줄을 보내면 서버 판정이 「관리자만 가능」(`role-denied`)으로 건너뛴다(화면에서는 권한 열이 숨어 있어 보낼 수 없지만 서버가 다시 막음). 역할 변경은 DB 가드(`guard_profile_update`)도 관리자만 허용한다.

### 줄 상태(`PlanStatus`)

신규 · 변경(이름·팀·권한, 바뀌는 내용 표시) · 변경 없음 · 팀 선택 필요(부서 담당자만) · 중지된 계정(건너뜀 — 목록에서 복구) · 이미 있는 성과관리팀·관리자 계정(건너뜀) · 기관 밖 메일(성과관리팀은 새로 등록 못 함) · 관리자만 가능(성과관리팀 권한) · 중복(표 안 앞 줄과 같은 메일) · 오류(이름/이메일 형식·없는 팀).

### 팀 추천 규칙(`lib/users/team-match.ts`)

- 비교용 정규화: 가운뎃점 변형(`· ㆍ ・ ･ • ∙ ⋅ ‧`)·마침표·쉼표 제거 → NFKC → 소문자 → 공백·괄호 제거.
- **자동 확정**은 오판 여지가 없는 경우뿐(팀명이 `teams.name` unique): ① 전체가 팀명과 같음 ② 괄호·슬래시·공백 등으로 나눈 조각 하나가 팀명과 같음(나머지 말이 있어도, 조각 둘 이상이 서로 다른 팀명이면 확정 안 함) ③ 본부명+팀명을 이어 씀. 본부 조각이 그 팀의 본부와 다르면 확정하되 경고.
- **추천**(사람이 골라야 반영): 끝말(팀·센터·단·TF)만 다름 0.97 / 팀명이 글에 포함 0.92 / 팀명의 일부만 적힘 / 글자 2-그램 Dice 계수 0.45 이상 상위 3개 / 본부만 적힘 → 그 본부의 팀들 / 팀명이 여러 개 적힘 → 그 팀들. 전파혁신전략/추진팀·검사관리/기획팀·기금○○팀 같은 비슷한 이름은 자동 선택하지 않는다.

## 과제 담당자 (`card_assignees`)

- 과제 × 부서 담당자, n:m (한 사람이 여러 과제, 한 과제에 여러 명). 기본키 `(card_id, user_id)`.
- 조건(트리거 `guard_card_assignee`, 서비스 키로 써도 적용): 사용자가 **활성 부서 담당자**이고 **사용자의 팀 = 카드의 팀**.
- 정리 트리거: 사용자의 `team_id`·`role`이 바뀌면 그 사용자의 지정을 지우고, 카드의 `team_id`가 바뀌면 그 카드의 지정을 지운다(어긋난 지정 방지). 앱은 팀이 바뀌면 새 팀 과제를 다시 지정한다.
- RLS: 읽기는 성과관리팀·관리자 전체 + 본인 행, 쓰기는 성과관리팀·관리자.
- 옆 창 「담당 과제」(`AssignmentEditor`): 그 사람 팀의 활성 과제를 사업별로 체크. 저장은 `setUserAssignments`(추가·제외 차이만 반영). 나중에 팀에 생긴 카드는 자동 지정되지 않는다.

## 삭제 = 사용 중지

`auth.users`를 참조하는 열 30개 중 27개(작성자·확정자·수정자 등)에 ON DELETE가 없어, 기록을 남긴 사용자는 지울 수 없고 감사 근거도 사라진다. 그래서 `profiles.active = false`로 중지한다.
- 중지하면 DB의 `my_role()`이 비어 RLS로 데이터가 즉시 막히고, `requireUser`가 `/login?blocked=1`로 보내며(앱 틀은 메뉴를 안 그림), 로그인 링크 발급은 Supabase auth ban(`876000h`)으로 막는다. 복구는 반대.
- 순서: 로그인 사용자 권한의 `profiles` update가 1행 이상 성공한 **뒤에** ban(서비스 키)을 건다.
- 중지된 계정은 담당자로 새로 지정할 수 없다(기존 지정은 남음).

## 기록·데이터 정정

- `access_events(actor_id, target_user_id, action, detail)`: `user_added`·`user_updated`·`user_deactivated`·`user_restored`·`assigned`·`unassigned`. 성과관리팀·관리자가 읽고 자기 이름으로만 남긴다. 기록 실패는 본 작업을 막지 않고 서버 로그에만 남는다.
- 본부 표기: 방송콘텐츠진흥팀의 본부 「방송미디어부」는 원본 오기(사용자 확인 2026-09-30) — 마이그레이션이 `teams.hq`를 「방송미디어본부」로 바로잡고(멱등), `HQ_CORRECTIONS`(`lib/db/seed-rows.ts`)가 재적재 때 되돌아가지 않게 한다. 카드 본문·`cards.hq`는 원본이라 건드리지 않는다. `teams.hq`는 표시·그룹용이며 권한에는 쓰지 않는다.
